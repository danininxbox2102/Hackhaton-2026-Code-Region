# СТАРТЕР — Electron + Capacitor (foundation)

One Vue 3/Vite frontend in **Frontend/**; no copied templates or duplicated state. Two wrappers:

| target | directory | engine |
| --- | --- | --- |
| Browser | Frontend | Vite / Vue |
| Windows, Linux, macOS | Desktop | Electron 45, bundled UI |
| Android, iOS | Mobile | Capacitor 8.6, bundled UI |

The existing **AppNative/** MAUI template is not involved. Both wrappers read the *same* Frontend/dist Vite build. Existing hash routes (#/, #/saved, #/account) work in custom Electron URL / Capacitor local origin.

## Required backend environment

**Native apps must call an HTTPS API reachable from the device.** The local Vite proxy (localhost:3000) works only in a browser on the development PC, *not* inside packaged apps.

Build the same web UI with:

PowerShell:

    $env:VITE_API_URL = "https://YOUR-REAL-API-HOST"
    node .\scripts\build-native.mjs

Shell:

    VITE_API_URL=https://YOUR-REAL-API-HOST node scripts/build-native.mjs

The script aborts if VITE_API_URL is missing/non-HTTPS/contains a path or credentials. It forces VITE_DATA_MODE=api, runs Vue typecheck and Vite build. **Do not include /api** at the end: existing client appends /api routes. The address is baked into the bundle (never embed API tokens here). Use a real TLS endpoint with CORS, not "localhost" in installed apps.

On Express, configure server-side CORS_ORIGIN as a comma-separated allowlist including the web origin and these native origins:

    https://localhost,capacitor://localhost,starter://app

Examples: CORS_ORIGIN=https://starterjob.ru,https://localhost,capacitor://localhost,starter://app

These are potential local WebView origins; verify actual Origin request headers in your platform/network log before deploying. CORS is **not authentication**; Bearer JWT remains required. If the backend only listens at 127.0.0.1:33316, that is a *database port*, not an app API endpoint.

## Desktop

Install independently:

    cd Frontend
    npm ci
    cd ../Desktop
    npm install

Development (two consoles):

    cd Frontend
    npm run dev -- --port 5173

    cd Desktop
    npm run dev

Packaged builds (with VITE_API_URL set in the shell):

    cd Desktop
    npm run pack:dir       # unpacked app, current OS
    npm run dist:win       # Windows NSIS on Windows
    npm run dist:linux     # AppImage on Linux
    npm run dist:mac       # DMG on macOS

Output is Desktop/release (ignored). For native installers add final app icons and code signing; unsigned installers will trigger OS warnings.

Security: sandboxed renderer, no Node integration, context isolation, no arbitrary popup windows, HTTPS-only external browser links, path-checked built-in starter://app files, CSP hashes of the existing inline theme script, and narrow IPC bridge for opening verified HTTPS employer links. In Electron, the app cannot silently navigate to external pages. HTTP employer links are intentionally blocked.

## Android

Install frontend as above, then:

    cd Mobile
    npm install
    npm run build:web         # requires HTTPS VITE_API_URL
    npm run android:init      # run once: creates Mobile/android/
    npm run android:sync
    npm run android:open      # Android Studio: build/debug APK

For subsequent frontend updates use npm run android:sync; do not run cap add twice. The Mobile/android native project generated by Capacitor should be committed after generation and review. Requires Android SDK, Java/JDK compatible with Capacitor 8, Android Studio. There is no APK in this PR until the native project is generated and built.

## iOS

Only on macOS with Xcode and signing:

    cd Mobile
    npm install
    npm run build:web
    npm run ios:init
    npm run ios:sync
    npm run ios:open

iOS provisioning / App Store signing are not configured in this foundation.

## Verification

    node --test tests/native-foundation.test.mjs Desktop/test/*.test.cjs
    cd Frontend && npm ci && npm run typecheck && npm run build

Electron/Android/iOS packaging depends on platform SDKs and internet access to download binaries, so CI only verifies the portable scaffold and existing Vue build. No Android/iOS project files or signed installers are claimed to exist yet.
